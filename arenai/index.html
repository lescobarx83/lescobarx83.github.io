03 // KEY FEATURES — PUNTOS FUERTES DE INGENIERÍA (AUDITORÍA FASE 1.4)

Ingeniería Interna: Cómo Funciona Realmente Cada Subsistema

Análisis técnico de los cinco pilares de ingeniería verificados en el código fuente de ArenAI: resolución de condiciones de carrera en duelos WebSockets, ingeniería de prompts pedagógicos, psicometría algorítmica, onboarding institucional por dominio/QR e interpolación cromática reactiva.

1. Motor de Batallas Síncrono con Resolución de Condiciones de Carrera (socketService.ts & BattleMinigame.tsx)

Implementa una máquina de estados distribuida por WebSockets para duelos académicos 1v1 en tiempo real con colas de matchmaking (waitingQueue) y gestión de salas activas (activeGames).

  • Barra Sudden Death de 8 Segundos: Cuando el primer jugador responde una pregunta, dispara el evento opponent_answered que activa un temporizador implacable de 8 segundos para el rival.
  • Cálculo de Impactos por Delta en Milisegundos: Evalúa deltas de tiempo (roundStartTime) y exactitud para calcular impactos normales (5–8% HP por ventaja de velocidad) o golpes críticos (25–30% HP por fallo rival).
  • Heartbeat de 2s y Tolerancia a Fallos: Monitorea desconexiones abruptas otorgando victoria automática por abandono y actualizando rachas (winStreak y utilizationIndex).
// Máquina de estados 1v1 en socketService.ts / StandaloneBattleSocket
socket.on("submit_answer", ({ questionIndex, answerIndex }) => {
  const elapsedMs = Date.now() - room.roundStartTime;
  socket.to(room.id).emit("opponent_answered", { suddenDeathSeconds: 8 });
  // Impacto Normal: 5–8% HP (velocidad) | Golpe Crítico: 25–30% HP (fallo rival)
  const damage = isRivalWrong ? calcCrit(25, 30) : calcSpeedDelta(elapsedMs, 5, 8);
  io.to(room.id).emit("round_result", { p1Health, p2Health, roundResult });
});

2. Ingeniería de Prompts Contextual y Tutoría Socrática Adaptativa (ai.ts, prompts.ts & Chatbot.tsx)

En lugar de un wrapper genérico de chat, el sistema construye dinámicamente un contexto pedagógico conectado con Google Cloud Vertex AI (gemini-2.0-flash-lite-001) y Ollama (DeepSeek-R1).

  • Inyección Multidimensional de Contexto: Combina el rol del usuario (Método Socrático guiado para estudiantes vs. Asistente de Planificación Curricular para profesores), el estilo cognitivo diagnosticado (Visual, Lógico, Kinestésico, Significativo), los temas activos y la personalidad de la mascota (Capybara o Sloth).
  • Restricción Pedagógica Anti-Spoiler: Prohíbe revelar respuestas directas al alumno, guiándolo mediante preguntas inductivas.
  • Motor Typewriter Asíncrono: Renderiza la salida caracter por caracter con soporte Markdown libre de bloqueos de UI.
// Construcción de System Prompt adaptativo (prompts.ts / geminiService.ts)
export function buildPedagogicalPrompt({ role, learningType, subject, mascot }) {
  if (role === "student") {
    return `[ROLE: SOCRATIC_TUTOR][PERSONA: ${mascot}][STYLE: ${learningType}]
NEVER reveal the direct solution for ${subject}. Formulate guided Socratic
questions tailored to a ${learningType} learner with step-by-step hints.`;
  }
  return `[ROLE: CURRICULUM_ARCHITECT] Generate lesson plans & rubrics for ${subject}.`;
}

3. Diagnóstico Cognitivo y Onboarding Algorítmico (PersonalityQuiz.tsx) + Dominio/QR (Register.tsx, Class_Creation.tsx)

Personalización psicométrica desde el primer inicio de sesión combinada con aprovisionamiento institucional automatizado.

  • Vectores de Afinidad Cognitiva ($\ge 25\%$): Cuestionario psicométrico multilingüe (ES/EN/ZH) que pondera las respuestas mediante vectores de afinidad (learningType), determinando el perfil dominante con umbrales de significancia $\ge 25\%$ y persistiéndolo para el tutor IA.
  • Detección Institucional por Dominio: Parsing inteligente de correos (@mep.go.cr, @ucr.ac.cr, @itcr.ac.cr) con autocompletado y bloqueo de seguridad en Register.tsx.
  • Inscripción Instantánea por QR: Generación en cliente de códigos QR vectoriales/DataURL en Class_Creation.tsx para unir alumnos a secciones vía /join/:code.

4. Sistema de Diseño Reactivo, Interpolación Cromática & Modelo Relacional de 18+ Entidades (ThemeContext.tsx, database/)

Arquitectura visual reactiva respaldada por un esquema relacional normalizado sobre MySQL 8 / openGauss con TLS.

  • 7 Paletas en Caliente + Interpolación $\text{RGB}_{\text{Red}} \to \text{RGB}_{\text{Teal}}$: ThemeProvider alterna instantáneamente entre 7 temas completos mientras Main_Student.tsx interpola continuamente el color de cada tema según el porcentaje de dominio.
  • Motor de Sprites Estocástico (AnimatedMascot.tsx): Ciclos de parpadeo aleatorios cada 4–6s y respuesta táctil/hover sincronizada con Howler.js.

-- Relaciones jerárquicas de prerrequisitos curriculares (database/schema.sql)
CREATE TABLE topic_father_son_relation (
  id_father_topic INT NOT NULL REFERENCES topic(id_topic),
  id_son_topic    INT NOT NULL REFERENCES topic(id_topic),
  correlation_coefficient DECIMAL(4,3) NOT NULL DEFAULT 0.750,
  PRIMARY KEY (id_father_topic, id_son_topic)
